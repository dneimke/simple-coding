# Review gate

When the pull request says it closes an issue, the review answers that issue's checklist. Anything else is a note, not a new assignment.

A blocking comment needs evidence. A performance comment cites the command and the numbers. A correctness comment cites the call that fails. Say when you did not run the check.

File at most three blocking comments. A blocker is a coder-visible break: lost data, a broken journey, or a gate that stays green when the bug returns. Wording, severity votes, and duplicate routes are notes.

The success line may claim only the checks that set the exit code.

When addressing a review, mark each blocker fixed, declined, or deferred, and name the check. Leave behavior the comment did not mention unchanged.
